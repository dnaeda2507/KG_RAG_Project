  1. OBJECTIVE
══════════════════════════════════════════════════════════════════════════

  Phase 3 generates the evaluation benchmark used in Phases 4 and 5.
  50 questions per domain (100 total) are created by traversing multi-hop
  paths in the Wikidata5M Neo4j graph, with each question automatically
  verified before inclusion.

  Requirements to meet:
    • At minimum 50 valid questions per domain
    • At least 30 two-hop questions  (≥ 60%)
    • At least 10 three-hop questions (≥ 20%)
    • At least 5 comparison-style questions (≥ 10%)
    • All question templates must have at least 3 distinct paths


══════════════════════════════════════════════════════════════════════════
  2. METHODOLOGY
══════════════════════════════════════════════════════════════════════════

  Step 1: Seed entity retrieval
    All domain seed entities (films for Cinema, clubs for Football) are
    fetched from Neo4j.

  Step 2: Path traversal
    For each seed, Cypher MATCH queries extend 2 or 3 hops along
    predefined relation sequences. Only paths where every node has a
    human-readable alias are retained.

  Step 3: Question instantiation
    A natural-language question template is filled with entity aliases.
    The last-hop node becomes the gold answer.

  Step 4: Verification checks
    ✔ Entity alias present in wikidata5m_entity.txt
    ✔ Answer entity is not null/empty
    ✔ Question and answer are different strings
    ✔ No duplicate (entity1, relation_chain, entity2) tuples
    ✔ Path length matches declared hop count

  Step 5: Deduplication & sampling
    Up to the required quota per template is sampled; further questions
    from a template are dropped until the global 50-question quota is met.

  Output format (JSON per question):
  {
    "id":            "TR_001",
    "question":      "natural language question text",
    "answer":        "canonical gold answer",
    "hop_type":      "2-hop",
    "template":      "Film→DIRECTOR→PLACE_OF_BIRTH",
    "entities":      ["Q_film", "Q_director", "Q_city"],
    "path":          [["Q_film","DIRECTOR","Q_dir"],["Q_dir","PLACE_OF_BIRTH","Q_city"]],
    "gold_answer":   "gold answer string"
  }

  6. KNOWN CHARACTERISTICS & LIMITATIONS
══════════════════════════════════════════════════════════════════════════

  1. Gold answer format follows Wikidata5M aliases verbatim
     "istanbul (turkey)" NOT "Istanbul". This creates a matching challenge
     because LLMs and Wikipedia answers use different capitalisation and
     punctuation. Soft-accuracy metric (partial match) was added to handle
     this.

  2. Many 2-hop PLACE_OF_BIRTH answers are "istanbul (turkey)"
     TR_001 through TR_008 all have the same gold answer. This introduces
     a distributional bias; models that guess "istanbul" get 8+ correct.

  3. Historical city name aliases
     "Q3640 = Angora, Turkey" (Ankara) — LLMs typically return "Ankara"
     not "Angora". The soft_accuracy metric handles some cases
     (e.g., "angora" in "ankara" fails; "ankara" not in "angora" fails).

  4. 3-hop COUNTRY answers all "turkiye"
     TR_031–TR_045 mostly have gold = "turkiye". This is factually
     correct (Turkish films → Turkish directors → Turkish cities →
     Turkey) but reduces discriminative power.

  5. Comparison questions (COMPARISON:: prefix) are excluded from all
     quantitative metrics as they require open-ended evaluation.
